# Comprehensive Missubibi Forecasting System - Implementation Plan

## Context

The user wants to build a "super advanced" forecasting system that:
- Integrates ALL models from the Sep16th folder (SARIMA, RF, LSTM, NN, TR)
- Supports multiple dimensions: Company, Product, Customer, Industry, Vendor
- Supports multiple granularities: Daily, Weekly, Monthly, Quarterly, Yearly
- Provides individual model forecasts + ensemble (weighted average)
- Uses real SQL data with a universal adapter so schema changes don't break models
- Keeps classification models (NN, TR) as separate features/exogenous signals

## Current State

**✅ Already Integrated (Forecasting):**
- SARIMA Engine (`backend/app/services/sarima_engine.py`) - statistical baseline
- XGBoost Engine (`backend/app/services/xgboost_engine.py`) - gradient boosting (lib issue on Mac)
- RandomForest Engine (`backend/app/services/randomforest_engine.py`) - ensemble trees
- LSTM Engine (`backend/app/services/lstm_engine.py`) - deep learning (needs log-mode fix deployed)

**✅ Already Integrated (Frontend):**
- Forecast Lab with SARIMA/RF/LSTM model selector
- Model comparison panel showing all 3 forecasts side-by-side
- Background job polling pattern for long-running forecasts

**❌ Not Integrated (Classification - Different Problem):**
- NN Classifier (`nn_engine_rev9`) - TF/Keras, predicts P(High Demand) per item/month
- TR Classifier (`tr_engine_rev8`) - Tabular Transformer, predicts P(Sold) per item/month

**❌ Missing:**
- Trend Regression forecaster (simple baseline)
- Ensemble endpoint (weighted average)
- Industry/Vendor dimensions
- Weekly/Daily/Quarterly/Yearly granularities
- Universal data adapter layer
- Demand Classifier page for inventory team

---

## Requirements & Constraints

### Functional Requirements
1. **Forecasting Stack**: 5 forecasters (SARIMA, XGB, RF, LSTM, TrendReg) + Ensemble
2. **Dimensions**: total, product, customer, industry, vendor
3. **Granularities**: monthly, weekly, daily, quarterly, yearly
4. **Ensemble**: Learned weights per dimension/granularity from CV
5. **Classifiers as Features**: NN/TR → exogenous signals for forecasters
6. **Demand Classifier Page**: Separate UI for item-level predictions

### Non-Functional Requirements
1. **Universal Data Adapter**: Single point of SQL schema coupling
2. **Schema Resilience**: New data → only adapter changes, models auto-adapt
3. **Performance**: Background jobs + caching (existing pattern)
4. **Type Safety**: Consistent ForecastResult interface across all engines

### Technical Constraints
- MySQL backend via SQLAlchemy (existing `get_sales_data()`)
- FastAPI background threads for long runs (existing pattern)
- React + Vite frontend (existing)
- Python 3.12, PyTorch for LSTM, statsmodels for SARIMA
- XGBoost has lib issue on Mac (known, document workaround)

### Phase 1: Foundation - Universal Data Adapter (Week 1)

**Files to Create:**

**Files to Modify:**

**Adapter Interface:**
```python
class DataAdapter:
    def get_monthly_series(self, dimension, dimension_value, value_col) -> pd.DataFrame
    def get_weekly_series(self, ...) -> pd.DataFrame
    def get_daily_series(self, ...) -> pd.DataFrame
    def get_quarterly_series(self, ...) -> pd.DataFrame
    def get_yearly_series(self, ...) -> pd.DataFrame
    def get_dimension_values(self, dimension) -> List[str]
    def get_industries(self) -> List[str]
    def get_vendors(self) -> List[str]
```

**SQL Strategy:**
- Single source of truth: `Sales_Order_Merged` + `Item` + `Customer` joins
- Dimension columns: `product_category_2` (product), `company_name` (customer), `fa_sub_industries` (industry)
- Vendor: Not in current schema → add placeholder, document need for vendor mapping table
- Granularity: Resample monthly data (weekly/daily via interpolation, quarterly/yearly via aggregation)

### Phase 2: Missing Forecasting Engines (Week 1-2)

#### 2.1 Trend Regression Engine
**File:** `backend/app/services/trend_engine.py`

Simple, interpretable baseline:
- OLS: `revenue ~ time + seasonal_dummies(month)`
- Optional: Fourier terms for seasonality
- Extrapolates trend + seasonal pattern
- Same interface as other engines (`run_forecast()`)

#### 2.2 Ensemble Engine
**File:** `backend/app/services/ensemble_engine.py`

```python
def run_ensemble_forecast(
    sales_df,
    dimension="total",
    dimension_value=None,
    value_col="revenue",
    horizon=12,
    fast=True,
    weights=None,  # dict model->weight, or None for learned
) -> ForecastResult
```

- Runs all 5 forecasters in parallel (thread pool)
- Weights: Default equal (0.2 each), or learned from walk-forward CV per dimension
- Returns weighted average + individual forecasts + model weights used
- Same `ForecastResult` format

### Phase 3: Classification Engines as Features (Week 2)

**Integration Point (in analytics.py):**
```python
def get_classifier_signals(next_month_date) -> dict:
    """Returns exogenous features for forecasters."""
    return {
        "nn_high_demand_count": count_items_nn_p_high_gt_0_7,
        "tr_sold_count": count_items_tr_p_sold_gt_0_7,
        "nn_high_demand_items": [...],  # top items
```

**Usage:**
- Call before forecaster runs
- Pass signals as exogenous regressors to SARIMA/XGB/RF/LSTM
- Cache classifier predictions (they're fast once models trained)

## Resolved Decisions

1. **Vendor data**: SQL tables exist; wire directly. Vendor column may be absent → adapter returns empty list gracefully.
2. **NN/TR models**: No exported models (.h5) yet. Build inference wrappers that load models if present, else return transparent mock/stub probabilities. Retrain monthly when a model file appears.
3. **Retraining**: Automatic (scheduled + on new data / cache invalidation).
4. **Ensemble weights**: Learned from day 1 — walk-forward CV per dimension/granularity, weight = inverse of WF error (MASE), floor at 0.05, regularized.
